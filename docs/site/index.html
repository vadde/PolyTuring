The Context Window Crisis & The Myth of Raw Grep

When autonomous coding agents are equipped only with primitive filesystem tools (cat, grep, find), three catastrophic failure modes inevitably emerge:

🔥 Context Window Saturation

Dumping 1,500-line source files into LLM prompts burns 80%+ of model attention on boilerplate, triggering early context window truncation, memory loss, and steep API latency.

🌫️ The "Blind Grep" Hallucination Trap

Simple keyword searches lack structural semantic awareness. They cannot distinguish a symbol definition from a comment, an import statement, or an unrelated variable, causing agents to patch the wrong symbols.

💥 Silent Cross-Boundary Blast Radii

When an agent refactors an interface or method signature without knowing all foreign callers across other packages, it causes cascading compilation failures and invisible downstream regressions.

Galaxy Subsystems & Louvain / Leiden Modularity Clustering

Software codebases are not flat hierarchies of directories. In reality, modern applications are scale-free, directed multi-graphs of functions, types, interfaces, and traits linked by call invocations, type references, and implementations. When an autonomous coding agent attempts to modify a codebase without architectural clustering, it suffers from context blindness: it cannot distinguish tightly-coupled internal modules from loose external boundaries.

Omni-Graph solves this by partitioning the entire AST graph into self-contained, cohesive architectural clusters called Galaxy Subsystems using a dual-phase Louvain and Leiden community detection engine.

Mathematical Formulation: Modularity Optimization ($Q$)
Omni-Graph discovers cohesive subsystems by maximizing Newman-Girvan network Modularity ($Q$) across directed, edge-weighted AST relations:

$$Q = \frac{1}{2m} \sum_{i,j} \left[ A_{ij} - \gamma \frac{k_i k_j}{2m} \right] \delta(c_i, c_j)$$
Parameters & Invariants:
  • $A_{ij}$: Weighted adjacency matrix representing architectural affinity between symbols $i$ and $j$.
  • $k_i = \sum_j A_{ij}$: Total degree (structural connectivity) of symbol node $i$.
  • $m = \frac{1}{2} \sum_{ij} A_{ij}$: Total edge weight across the entire repository graph.
  • $\gamma$: Resolution parameter governing community scale ($\gamma = 1.0$ standard, calibrated to prevent micro-cluster fragmentation).
  • $\delta(c_i, c_j)$: Kronecker delta ($\delta = 1$ if symbols $i$ and $j$ belong to the same Galaxy $c$, else $0$).

⚖️ Edge-Weighted Semantic Affinity

Not all code links carry equal architectural weight. Omni-Graph applies strict domain weights: IMPLEMENTS ($w = 3.0$), CALLS ($w = 2.0$), TYPE_REF ($w = 1.5$), and IMPORTS ($w = 1.0$).

🛡️ Louvain vs. Leiden Resolution

While standard Louvain greedily aggregates nodes, it can trap symbols in disconnected sub-communities. Omni-Graph adopts the Leiden refinement step, guaranteeing that every discovered galaxy is internally well-connected.

⚡ Two-Phase Dynamic Re-Clustering

Phase 1 (Instant Inheritance): File edits preserve existing galaxy assignments in SurrealDB via MERGE.
Phase 2 (Quiescent LPA): After 3.5s of edit silence, seed-preserving Label Propagation updates macro boundaries with zero ID thrashing.

Robert C. Martin Coupling Metrics & Dynamic Blast Radius Contracts

Once Galaxy Subsystems are clustered, Omni-Graph analyzes cross-boundary dependency vectors using Robert C. Martin's package metric formulations. This allows agents to quantify risk before writing a single line of refactored code:

📥 Afferent Coupling ($C_a$)

The number of external symbols outside this galaxy that depend upon symbols inside this galaxy. Measures incoming responsibility.

📤 Efferent Coupling ($C_e$)

The number of external symbols that symbols inside this galaxy depend upon. Measures outgoing structural dependency.

📐 Instability Metric ($I$)

Calculates resistance to change: $$I = \frac{C_e}{C_a + C_e} \quad (0 \le I \le 1)$$ $I=0$ indicates maximum stability (hard to change); $I=1$ indicates maximum volatility (easy to change).

Architectural Role Instability Threshold Subsystem Characteristics Agent Modification Strategy
Core Foundation $I \le 0.25$ Heavy incoming dependencies ($C_a \gg C_e$), shared domain types, zero external knowledge. CRITICAL RISK: Wide blast radius. Agent must preserve backward-compatible signatures.
Domain Service $0.25 < I \le 0.65$ Balanced business logic, moderate internal abstractions with external service calls. MODERATE RISK: Agent must verify intra-galaxy and direct caller contracts.
Orchestrator / Leaf $I > 0.65$ High outgoing dependencies ($C_e \gg C_a$), API controllers, CLI command routers, leaves. LOW RISK: Contained blast radius. Agent can safely refactor implementation details.
Dynamic Blast Radius Endpoint: GET /api/galaxy/boundary?symbol=X
Before an agent refactors any symbol, the pre-tool hook queries the symbol's boundary contract. Omni-Graph returns:

• Containment Status: 🛡️ Contained Internal (all callers reside in same galaxy), ⚠️ Boundary Crossing (foreign callers detected), or 🔌 Isolated (leaf / entrypoint).
• Caller Provenance: Exact line numbers, files, and galaxy IDs of every external caller.
• Agentic Advice: Concrete heuristics (e.g., "Symbol is called by 14 external callers in galaxy 'api_gateway'. Do NOT alter parameters without default fallbacks.").

Ephemeral Branch Fabric (EBF) & Git Worktrees

Coding agents frequently branch or create Git worktrees to isolate experimental code and execute parallel strategies. Traditional code indexing tools either re-index the entire multi-gigabyte repository from scratch or fail completely. Omni-Graph solves this with the Ephemeral Branch Fabric (EBF):

💡 Layman's Mental Model: What is a Git Worktree?
Think of Git Worktrees like having multiple browser tabs open for the exact same website at the same time:

In normal Git, if you want to switch from a payment feature to fix an urgent checkout bug, you must run git stash, run git checkout bugfix, and restart your compiler or local dev server.

With Git Worktrees, you have multiple physical folders on disk sharing the same underlying Git history. You (or 4 parallel AI agents) can work on feat-stripe-v2 and refactor-auth-jwt simultaneously in separate folders without branch switching conflicts.

The Problem with other indexers: They get confused, treat each folder as an unrelated duplicate repository, or force you to re-index the whole project from scratch on every branch switch.
The Omni-Graph Solution: Point Omni-Graph at the main project folder once. It automatically discovers all active worktree folders, links their lineage, indexes them in parallel, and live-updates whichever folder you edit in real time!

⚡ O(1) Worktree Pointer Peeking

Instead of spawning slow subshells (git rev-parse), Omni-Graph reads the .git worktree pointer file directly in Rust in under 5 microseconds, resolving parent repository root, branch name, and lineage.

🚀 Top-Down Fleet Auto-Cascade

Ingesting a trunk parent repo automatically inspects .git/worktrees/*, locates all active sibling checkouts, asynchronously indexes each branch, and attaches concurrent live file watchers.

🌱 Prior LPA Seed Inheritance

When clustering a new worktree, Omni-Graph inherits community IDs from the parent workspace. Only modified files shift, preserving 99% cluster visual stability across branches.

🔄 Dynamic Fleet Synchronizer

POST /api/worktrees/sync sweeps registered workspaces, discovers newly checked-out worktrees, cascades indexing, and aligns watcher daemons without restarts.

🧹 Automatic Dead Worktree GC

When an agent deletes a temporary worktree, /api/workspaces immediately sweeps SurrealDB and purges dead nodes, edges, and watchers, eliminating zombie workspace pollution.

🌲 Worktree Hierarchy & Delta UI

Worktrees are cleanly nested under their parent repository (worktrees: [...]), with branch selectors and glowing delta halos for modified AST nodes in Cosmograph.

Polyglot AST Grammar & Struct Field Extraction

Omni-Graph utilizes Tree-Sitter grammars compiled natively in Rust. Unlike shallow regex matchers, Omni-Graph models true language semantics across four enterprise languages:

  • Rust: Functions, methods in impl blocks (with DECLARES edges from structs), struct declarations with child field_declaration nodes (with CONTAINS and REFERENCES edges), enum_item, trait_item, macro_definition, and macro_invocation.
  • Go: Package declarations, function declarations, method declarations with pointer receiver binding, type_spec structs with member field_declaration nodes, and discrete import_spec symbols.
  • TypeScript / JavaScript: Lexical arrow functions, classes, interface_declaration with child property_signature nodes, type aliases, and multi-symbol named imports (import { A, B }).
  • Python: Synchronous and async coroutine definitions, class definitions with multi-inheritance tracking, call sites, and multi-symbol imports (from m import A, B).
Relational Edge Graph Schema
Every edge in the linked_to table models directed relationships:
$$\text{Node}_{\text{source}} \xrightarrow[\text{category}]{\text{edge\_type}} \text{Node}_{\text{target}}$$ Where $\text{edge\_type} \in \{\text{CALLS}, \text{IMPORTS}, \text{CONTAINS}, \text{IMPLEMENTS}, \text{REFERENCES}\}$ and $\text{category} \in \{\text{EXTRACTED}, \text{INFERRED}\}$.

Two-Tier Context Condenser & Graph-RAG Token Budget Math

A common failure mode in code assistants is context starvation: a retrieval tool dumps 8,000 tokens of raw source code, blowing past agent context windows and truncating essential architectural call graphs. Omni-Graph enforces a mathematical token budget guarantee:

Mathematical Budget SLA: $\le 1,500$ Tokens
Given that 1 LLM token $\approx 4$ characters of source code, the total character budget is capped at $C_{\text{max}} = 6,000$ characters:

$$C_{\text{total}} = C_{\text{root}} + \min(C_{\text{neighbors}}, 3800) + C_{\text{edges}} + C_{\text{macro}} \le 6,000 \text{ chars}$$
1. Seed / Root Symbols ($C_{\text{root}}$): Receive full code snippets (bounded to 300 chars max).
2. 1-Hop Neighbors ($C_{\text{neighbors}}$): Compressed to concise 1-line signatures (e.g. fn authenticate(user: &User) -> Result), strictly bounded at 3,800 characters.
3. Structural Graph Traces ($C_{\text{edges}}$): Reserved $\ge 1,800$ characters for structural relations: source ──[CALLS]──▶ target.
4. Result: Guaranteed $\le 1,500$ tokens regardless of graph density or codebase scale!

SurrealDB Relational Indexing & Zero-Blackout Re-indexing

SurrealDB v2 handles both relational graph traversals and HNSW vector searches. In Round 4, four dedicated relational indexes were added to linked_to:

SurrealQL · src/db/schema.surql 
-- Sub-millisecond graph edge traversals & caller lookups
DEFINE INDEX idx_edge_workspace ON TABLE linked_to FIELDS workspace;
DEFINE INDEX idx_edge_in        ON TABLE linked_to FIELDS in;
DEFINE INDEX idx_edge_out       ON TABLE linked_to FIELDS out;
DEFINE INDEX idx_edge_out_ws    ON TABLE linked_to FIELDS workspace, out;
DEFINE INDEX idx_edge_in_ws     ON TABLE linked_to FIELDS workspace, in;

During live file modifications, the live watcher daemon performs an atomic zero-blackout swap: the HuggingFace TEI vector embedding is computed prior to pruning previous AST nodes. This eliminates the 404 deletion gap from ~250ms down to $\approx 1$ms.

Agent Work-in-Progress (WIP) Recovery & Disambiguation

Autonomous coding companions occasionally suffer from context window resets, token ceiling truncations, IDE crashes, or system reboots. Without telemetry, an assistant entering a codebase has no recollection of recent file modifications, pending tasks, or error blockers.

Session Explorer introduces the Agent WIP Recovery System (/most-recent-wip and make session-wip). It extracts recent user prompts, modified files, executed commands, and error logs directly from local JSONL transcripts.

🛑 The Multi-Session Disambiguation Invariant
What happens when a codebase has multiple parallel sessions?

If a developer has three parallel sessions open (e.g. one for backend refactoring, another for CSS polishing, and another for CI debugging), a recovering assistant must NEVER guess or blindly assume the latest session is the target. Doing so leads to catastrophic context corruption!

The Invariant: When multiple sessions match a workspace, the engine automatically halts, returns a structured candidate table with timestamps and prompt previews, and requires the coding assistant to STOP and ask the human user which session to resume.

Chapter 04 · Engineering Rigor & Governance

Engineering Rigor, SDD Constitution & Verification Gates

Spec-Driven Development · Agentic Reconnaissance Gate · Continuous Documentation Sync
▼

Autonomous development requires extreme discipline. Without formal contracts and automated verification gates, agent-generated code rapidly decays into technical debt. PolyTuring enforces a constitutional engineering framework across every tool in the monorepo:

Spec-Driven Development (SDD) & SDLC Constitution

In traditional codebases, autonomous coding agents rapidly diverge from human architectural intent because documentation and code live in disconnected universes. In vadde/PolyTuring, every single line of production code is governed by Spec-Driven Development (SDD):

📋 Contract Before Code

Every tool, script, and workflow begins with an airtight specification in specs/catalog/<tool>.md defining verifiable functional requirements, testable acceptance criteria, and non-functional guarantees.

🔄 SDLC Lifecycle Finite State Machine

Tools traverse deterministic phases: draft → spec-review → in-progress → testing → review → released. Advancement is cryptographically blocked unless all checklist gates pass.

🧭 Continuous Session Memory

Every tool folder contains a mandatory CONTEXT.md (agent state snapshot) and append-only DEVLOG.md. Agents never start from zero or lose historical context between compacting sessions.

Theoretical Principle: The Reflexion Pattern
When tests fail or architectural invariants are breached, agents are forbidden from applying blind heuristic patches. Instead, agents must apply the Reflexion loop: extract the root cause from the compiler/runtime, correlate with the spec requirement, document the failure hypothesis, and execute a mathematically minimal, targeted correction.

The Agentic Defense Shield & Reconnaissance Gates

Large Language Models possess context windows, but context windows are finite and vulnerable to noise contamination. Blindly reading a 3,000-line source file wastes tokens and destroys reasoning capabilities. The monorepo enforces the 3-Tier Omniverse Reconnaissance Ladder:

The 150-Line Gate Invariant
Directly viewing or catting more than 150 lines of source code without querying Omni-Graph's AST or condenser first is an immediate anti-pattern. The PreToolUse hook halts unauthorized large reads and directs the agent to retrieve exact AST symbol definitions or condensed slices.
