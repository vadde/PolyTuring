Chapter 00 · Section 01

Spec-Driven Development (SDD) & SDLC Constitution

Contract before code, numbered requirements (R-XXX), status verification gates
▼

In traditional codebases, autonomous coding agents rapidly diverge from human architectural intent because documentation and code live in disconnected universes. In vadde/tool-scripts, every single line of production code is governed by Spec-Driven Development (SDD):

📋 Contract Before Code

Every tool, script, and workflow begins with an airtight specification in specs/catalog/<tool>.md defining numbered requirements (R-XXX), acceptance criteria (AC-XXX), and non-functional guarantees (NF-XXX).

🔄 SDLC Lifecycle Finite State Machine

Tools traverse deterministic phases: draft → spec-review → in-progress → testing → review → released. Advancement is cryptographically blocked unless all checklist gates pass.

🧭 Continuous Session Memory

Every tool folder contains a mandatory CONTEXT.md (agent state snapshot) and append-only DEVLOG.md. Agents never start from zero or lose historical context between compacting sessions.

Theoretical Principle: The Reflexion Pattern
When tests fail or architectural invariants are breached, agents are forbidden from applying blind heuristic patches. Instead, agents must apply the Reflexion loop: extract the root cause from the compiler/runtime, correlate with the spec requirement, document the failure hypothesis, and execute a mathematically minimal, targeted correction.

The Agentic Defense Shield & Reconnaissance Gates

Large Language Models possess context windows, but context windows are finite and vulnerable to noise contamination. Blindly reading a 3,000-line source file wastes tokens and destroys reasoning capabilities. The monorepo enforces the 3-Tier Omniverse Reconnaissance Ladder:

The 150-Line Gate Invariant
Directly viewing or catting more than 150 lines of source code without querying Omni-Graph's AST or condenser first is an immediate anti-pattern. The PreToolUse hook halts unauthorized large reads and directs the agent to retrieve exact AST symbol definitions or condensed slices.

Ephemeral Branch Fabric (EBF) & Git Worktrees

Coding agents frequently branch or create Git worktrees to isolate experimental code and execute parallel strategies. Traditional code indexing tools either re-index the entire multi-gigabyte repository from scratch or fail completely. Omni-Graph solves this with the Ephemeral Branch Fabric (EBF) (Requirements R-051 to R-059):

⚡ O(1) Worktree Pointer Peeking

Instead of spawning slow subshells (git rev-parse), Omni-Graph reads the .git worktree pointer file directly in Rust in under 5 microseconds, resolving parent repository root, branch name, and lineage (R-051).

🚀 Top-Down Fleet Auto-Cascade

Ingesting a trunk parent repo automatically inspects .git/worktrees/*, locates all active sibling checkouts, asynchronously indexes each branch, and attaches concurrent live file watchers (R-059).

🌱 Prior LPA Seed Inheritance

When clustering a new worktree, Omni-Graph inherits community IDs from the parent workspace. Only modified files shift, preserving 99% cluster visual stability across branches (R-053).

🔄 Dynamic Fleet Synchronizer

POST /api/worktrees/sync sweeps registered workspaces, discovers newly checked-out worktrees, cascades indexing, and aligns watcher daemons without restarts (R-059).

🧹 Automatic Dead Worktree GC

When an agent deletes a temporary worktree, /api/workspaces immediately sweeps SurrealDB and purges dead nodes, edges, and watchers, eliminating zombie workspace pollution (R-054).

🌲 Worktree Hierarchy & Delta UI

Worktrees are cleanly nested under their parent repository (worktrees: [...]), with branch selectors and glowing delta halos for modified AST nodes in Cosmograph (R-055, R-056).

Multi-Worktree Concurrency & Branch Isolation
When parallel AI agents develop multiple strategies simultaneously (such as ti-strat-089 through ti-strat-092), EBF enforces strict SurrealDB record-level partition isolation (workspace = "<worktree_id>") while sharing the parent LPA community cluster seeds. Each worktree enjoys independent sub-100ms incremental file watching without cross-talk or lock contention.

Polyglot AST Grammar & Struct Field Extraction

Omni-Graph utilizes Tree-Sitter grammars compiled natively in Rust. Unlike shallow regex matchers, Omni-Graph models true language semantics across four enterprise languages:

  • Rust: Functions, methods in impl blocks (with DECLARES edges from structs), struct declarations with child field_declaration nodes (with CONTAINS and REFERENCES edges), enum_item, trait_item, macro_definition, and macro_invocation.
  • Go: Package declarations, function declarations, method declarations with pointer receiver binding, type_spec structs with member field_declaration nodes, and discrete import_spec symbols.
  • TypeScript / JavaScript: Lexical arrow functions, classes, interface_declaration with child property_signature nodes, type aliases, and multi-symbol named imports (import { A, B }).
  • Python: Synchronous and async coroutine definitions, class definitions with multi-inheritance tracking, call sites, and multi-symbol imports (from m import A, B).
Relational Edge Graph Schema
Every edge in the linked_to table models directed relationships:
$$\text{Node}_{\text{source}} \xrightarrow[\text{category}]{\text{edge\_type}} \text{Node}_{\text{target}}$$ Where $\text{edge\_type} \in \{\text{CALLS}, \text{IMPORTS}, \text{CONTAINS}, \text{IMPLEMENTS}, \text{REFERENCES}\}$ and $\text{category} \in \{\text{EXTRACTED}, \text{INFERRED}\}$.

Two-Tier Context Condenser & Graph-RAG Token Budget Math

A common failure mode in code assistants is context starvation: a retrieval tool dumps 8,000 tokens of raw source code, blowing past agent context windows and truncating essential architectural call graphs. Omni-Graph enforces a mathematical token budget guarantee:

Mathematical Budget SLA: $\le 1,500$ Tokens
Given that 1 LLM token $\approx 4$ characters of source code, the total character budget is capped at $C_{\text{max}} = 6,000$ characters:

$$C_{\text{total}} = C_{\text{root}} + \min(C_{\text{neighbors}}, 3800) + C_{\text{edges}} + C_{\text{macro}} \le 6,000 \text{ chars}$$
1. Seed / Root Symbols ($C_{\text{root}}$): Receive full code snippets (bounded to 300 chars max).
2. 1-Hop Neighbors ($C_{\text{neighbors}}$): Compressed to concise 1-line signatures (e.g. fn authenticate(user: &User) -> Result), strictly bounded at 3,800 characters.
3. Structural Graph Traces ($C_{\text{edges}}$): Reserved $\ge 1,800$ characters for structural relations: source ──[CALLS]──▶ target.
4. Result: Guaranteed $\le 1,500$ tokens regardless of graph density or codebase scale!

SurrealDB Relational Indexing & Zero-Blackout Re-indexing

SurrealDB v2 handles both relational graph traversals and HNSW vector searches. In Round 4, four dedicated relational indexes were added to linked_to:

SurrealQL · src/db/schema.surql 
-- Sub-millisecond graph edge traversals & caller lookups
DEFINE INDEX idx_edge_workspace ON TABLE linked_to FIELDS workspace;
DEFINE INDEX idx_edge_in        ON TABLE linked_to FIELDS in;
DEFINE INDEX idx_edge_out       ON TABLE linked_to FIELDS out;
DEFINE INDEX idx_edge_out_ws    ON TABLE linked_to FIELDS workspace, out;
DEFINE INDEX idx_edge_in_ws     ON TABLE linked_to FIELDS workspace, in;

During live file modifications, the live watcher daemon performs an atomic zero-blackout swap: the HuggingFace TEI vector embedding is computed prior to pruning previous AST nodes. This eliminates the 404 deletion gap from ~250ms down to $\approx 1$ms.

Chapter 02 · Secondary Tool

Session Explorer: Agent Observability & Telemetry

Go 1.22+ Single Binary · Bun Embedded Frontend · JSONL Trajectory Telemetry
▼

Session Explorer is a standalone intelligence browser for Antigravity IDE agent conversation histories. It parses JSONL transcripts located in ~/.gemini/antigravity-ide/brain/, indexing tool calls, execution errors, user prompt intents, and agent reasoning traces.

Go + Bun Standalone Binary Architecture

Built for zero runtime friction, Session Explorer embeds its entire web application, marked.js markdown engine, and syntax highlighting directly inside the compiled Go binary using //go:embed:

⚡ 200ms Concurrent Ingestion

Concurrently parses tens of thousands of JSONL transcript lines in under 200 milliseconds using Go goroutine worker pools.

📊 Dual-Source Telemetry

Correlates agent tool calls with Omni-Graph LSP usage, estimating tokens saved by preventing full-file dumps.

One-click export of any agent conversation trajectory to Markdown (.md) or structured JSON (.json).
